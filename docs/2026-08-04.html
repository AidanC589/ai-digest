Engineering & AI Workflows

The AI Productivity Gap
Data-grounded analysis showing AI delivers ~15% daily time savings for senior engineers (who spend relatively little time coding) vs. ~25% for juniors; the parts AI doesn't help with — requirements analysis, system reasoning, cross-team coordination — are exactly where senior time goes, so productivity expectations need recalibrating
Don't be a meat proxy
Niklas Gruhn's term for people who blindly relay AI output without reading or validating it; directly relevant to anyone reviewing AI-generated code — the review step is where you add value, not the generation step
Quoting David Crawshaw's prompt
Concrete prompt pattern for autonomous maintenance: a nightly cron job running "fetch upstream changes to \ and rebase all local changes on top of upstream; check that the software works as intended and replace the current version" — a tight, repeatable agent task worth stealing
Devtools must be open source (exe.dev)
Simon Willison notes LLMs have made the open-source "examine and modify" promise actually practical: "tell Codex or Claude Code to checkout and build X and then come back ten minutes later" — friction for exploring unfamiliar codebases is now near zero
Quoting Steve Yegge
Steve Yegge reports Claude Opus 4.7 introduced a "just two more things" convergence failure in his coding agent framework Gas Town, where the model perpetually wanted to refine itself rather than do real work — a concrete regression to watch for if you're running long agentic loops with Opus 4.7
