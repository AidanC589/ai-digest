New release of LLM adds support for reasoning traces, OpenAI Responses, server-side tools, and smarter logging
LLM 0.32 now streams reasoning traces to stderr (keeping stdout clean for piping), supports server-side tools like CodeInterpreter and WebSearch, and introduces a stream_events() API that handles the mixed-type responses modern models actually return — reasoning chunks, text, tool calls, and image attachments as distinct typed events.
Unpacking ChatGPT Work: the Agent for a Billion Users
Detailed external reconstruction of ChatGPT Work's architecture: it runs in an isolated microVM (8 CPUs, 20GB RAM for Pro), uses the Codex harness for sub-agents, and connects to Slack/email/Drive/CRMs via plugins — useful reading for anyone thinking about how to design multi-tool agentic workflows or compare approaches with Claude Code.
llm-anthropic 0.26
The updated plugin brings Claude 5 models (Fable, Sonnet, Opus) with simplified thinking controls: thinking_effort now takes low/medium/high/xhigh/max, Claude 5 models think by default, and -o thinking 0 disables it for Sonnet/Opus — Fable always thinks. Old thinking_budget and thinking_display options are gone.

llm-anthropic 0.26
The new -R/--hide-reasoning flag omits reasoning from both responses *and* logs, which reduces stored token volume if you're logging at scale and don't need the thinking traces for every run — useful for high-volume batch tasks where you only care about the output.
