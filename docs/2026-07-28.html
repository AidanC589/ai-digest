Engineering & AI Workflows

Don't ask an LLM for a confidence score
A well-argued post explaining why LLM-generated confidence scores are "psychological safety tricks" with no scientific validity; if your AI code review pipeline outputs a confidence field, it's lying to you. The who-watches-the-watchmen regression problem alone makes numeric self-assessment untrustworthy — flag this pattern in any AI-generated code you review.
An opinionated guide to which AI to use to do stuff
Ethan Mollick's guide has shifted decisively toward agentic modes; Claude's "Cowork" and "Code" modes now occupy the same conceptual space as ChatGPT's "Work" and "Codex" but with different naming — useful orientation if you're deciding which agent mode to route tasks through.
Learning When to Reason for Text-to-SQL via SFT and DPO
AutoThinkSQL demonstrates that letting a model dynamically skip chain-of-thought for simple queries cuts output tokens by ~24% and latency by ~17% with no benchmark regression; the principle transfers directly to any agentic workflow where you're forcing reasoning on every subtask regardless of complexity.
Evaluating the Impact of Reviewer Guideline Design on LLM-Based Automated Peer Review
Study finds that structured, practice-refined guidelines outperform "reviewer-imitating" prompts generated from real reviews, and that strict rubric-style scoring *degrades* LLM review quality; if you're prompting Claude to score AI-generated code on a rigid 1–10 scale, this suggests you'd get better signal with holistic, criteria-based prompts instead.
Professor's invisible prompt trap catches 32/35 students cheating with AI
White-text prompt injection in a document caused 91% of students to submit nonsensical AI output unchecked; a direct reminder that AI-assisted workflows with no human review of outputs are a single injected instruction away from catastrophic failure — relevant for any pipeline that ingests external documents before passing them to an agent.
