General AI Developments

Is AI Reasoning Right for the Wrong Reasons?
Quanta's science journalist digs into the contradictory research: LRMs win IMO gold and solve open math problems, yet also fail on simple analogical puzzles via "surface-level shortcuts." The honest takeaway from researcher Melanie Mitchell: "It works" — but generalizable reasoning vs. sophisticated pattern-matching remains genuinely unresolved, which matters for how much you trust AI-generated code logic.
Google fixed more Chrome bugs in June than over the past two years, thanks to AI
Google's Gemini-powered vulnerability agent found a 13-year-old sandbox escape in Chrome, and now runs across the full codebase with a "critic" agent reviewing SECURITY.md files. Practical takeaway: AI-driven security audits at this scale are real and productive, but Google runs them air-gapped with strict allowlists — a useful model for anyone deploying code-scanning agents.

Engineering & AI Workflows

Stateless MCP has recaptured my interest (and inspired mcp-explorer and datasette-mcp)
MCP 2.0 (spec date 2026-07-28) collapses the old two-request handshake into a single HTTP call, eliminating session state entirely. This makes MCP servers far easier to audit, host, and drive with smaller local models — a significant workflow improvement for anyone building tool-augmented agents.
smevals - a small eval suite for evaluating models, prompts, and harnesses
Simon Willison's third iteration on evals tooling: uvx smevals lets you define YAML-based eval suites, run them across multiple model configs (including different system prompts and harnesses), grade results, and serve an HTML report. Directly useful for comparing AI code quality across model versions or prompt changes.
Everyone is building LLM routers, we deprecated ours
After 4 months and 7,000 users, Manifest found routing introduced more problems than it solved: prompt complexity can't be judged from the prompt alone (tool calls reveal it later), prefix caching already handles most cost reduction better than routing, and model-switching breaks consistency in agentic workflows. Strong argument for picking one capable model and sticking with it.

DeepSeek V4 Flash 0731 is a post-training-only update (same 284B/13B-active architecture) that jumped Terminal-Bench from 56.9 → 82.7 and cut output token usage 12% vs. predecessor. At $0.14/$0.28 per 1M tokens with a 98% cache-hit discount to $0.0028/M cached, it's a strong candidate for cost-sensitive agentic coding pipelines. Community notes gains are best realized with lighter harnesses and cache-friendly deployment, not heavy orchestration.
deepseek-ai/DeepSeek-V4-Flash-0731
Simon Willison's hands-on note: reasoning effort level matters significantly — default reasoning gave a poor result, but --reasoning_effort high delivered much better output. Flag to set explicitly in any pipeline using this model.

Token Saving Techniques

Everyone is building LLM routers, we deprecated ours
Manifest found that prefix caching alone (75–90% cheaper than uncached inputs) outperforms dynamic model routing for cost reduction, because system prompts and conversation history sit at the start of the prompt where prefix cache is most effective. Adding router stickiness (always returning to the initially chosen model once a session is cached) captures most of the savings without the consistency tradeoffs.
not much happened today
DeepSeek V4 Flash 0731 reports a 12% reduction in output token usage versus its predecessor, plus a 98% cache-hit discount ($0.0028/M cached tokens vs $0.14/M uncached). For high-volume agentic pipelines, structuring prompts to maximise cache hits on this model could dramatically cut costs.
