## Engineering & AI Workflows
- [Calling the AI bluff: "Do not guess" cut made-up claims from 71% to 20%](https://earnanhonestdollar.com/bench) — A simple instruction addition ("Use null for any field whose value is not on the page. Do not guess.") cut hallucinated extraction fields from 70.7% to 20.2% across 16 models; a cheap secondary model checking each returned value caught most remaining fabrications for under a cent per run — a pattern directly reusable for verifying AI-generated outputs.
- [Auditing and Repairing LLM-as-Judge Failures in a Production Text-to-SQL Pipeline](https://arxiv.org/abs/2609.30290) — A production LLM-judge (gpt-4o-mini) agreed with human graders at only kappa=0.04 on hard cases, mostly due to a "grade-hallucination" failure mode; swapping to a self-hosted Qwen model matched a much pricier model's agreement at 1/300th the cost, and unanimity-routed ensembles of three strong judges hit kappa=0.79 — useful reference if you rely on LLM review gates.
- [Quoting Muse AI Agent](https://simonwillison.net/2026/2026/Sep/28/muse-ai-agent/) — A real transcript of an autonomous agent's auto-reply falsely confirming availability and causing a bad customer interaction — a concrete reminder that giving agents unsupervised "confirm" actions needs guardrails, not just better prompts.
- [Bootstrapping Conversational Recommendation Agents At Spotify](https://arxiv.org/abs/2609.30297) — Spotify's self-improvement loop (variance-based contrastive optimization + a coding agent that auto-fixes planning/tool-use errors) beat a heavily hand-tuned prompt by +8% quality and drove +14% listening and +5% WAU in A/B tests — a good template for iterating agent prompts at scale.
- [Adding logit penalty for "wait", "maybe" and "perhaps" to Qwen models improves their accuracy](https://www.reddit.com/r/LocalLLaMA/comments/1wromzr/adding_logit_penalty_for_wait_maybe_and_perhaps/) — Penalizing "overthinking" hedge tokens during reasoning improved MATH-500 accuracy across quantization levels (e.g., BF16 74%→84%) while cutting reasoning-token length ~11–19%, suggesting hedge-word suppression as a cheap accuracy/efficiency lever for reasoning models.

## Token Saving Techniques
- [Cartograph: Federated Tool Discovery with Operator-Attested Retrieval for AI Agents](https://arxiv.org/abs/2609.30293) — An MCP proxy that exposes 3 discovery tools instead of loading 374 tool definitions, cutting a measured top-5 discovery exchange from 42,450 tokens to 475 while improving retrieval accuracy (R@5 0.816 vs 0.592 baseline) — directly applicable if your agent setups pull in large MCP tool catalogs.
