## Engineering & AI Workflows
- [[AINews] Muse Spark 1.3 matches GPT-5.6-Sol, confirming Meta Superintelligence as the newest Frontier Lab](https://www.latent.space/p/ainews-muse-spark-13-matches-gpt) — Stanford is replacing 85% of its Fall 2025 software engineering syllabus with agent skills, context engineering, MCP portals, agent-ready codebase design, and agentic code review — students now ship real PRs into OSS repos as coursework, a strong signal of where "engineering" is heading.
- [LLM Judges Verify Presence, Not Absence: Omission Blindness in AI Clinical Notes](https://arxiv.org/abs/2608.31016) — New research shows LLM-as-judge setups reliably catch fabricated/incorrect content but systematically fail to flag *missing* information — directly relevant if you're using an LLM to review another model's code or docs for completeness.
- [GLM 5.3 Flash makes a black hole Minecraft mod running locally on 4x RTX PRO 6000 WS](https://www.reddit.com/r/LocalLLaMA/comments/1w5gk2b/glm_53_flash_makes_a_black_hole_minecraft_mod/) — A concrete example of the "prompt, review, iterate" loop in practice: ~9 hours and 7.6M output tokens across many review rounds to get a working Fabric mod, illustrating how much iteration real agentic coding tasks still need.
- [Qwen3.8-Flash-Next on 2x3090 + DDR4: 17 → 25-29 t/s decode with the expert cache PR](https://www.reddit.com/r/LocalLLaMA/comments/1w5vjp6/qwen38flashnext_on_2x3090_ddr4_17_2529_ts_decode/) — A GPU-resident LRU expert cache nearly doubles decode speed on coding prompts by exploiting the fact that consecutive tokens reuse the same MoE experts 80-85% of the time — a useful pattern for anyone running local coding agents on consumer hardware.

## Token Saving Techniques
- [How Do Prompt Variations Affect Energy Consumption in On-Device LLMs?](https://arxiv.org/abs/2609.01798) — Cognitive load in a prompt mainly drives per-token energy cost, while phrasing pattern mainly drives total token count — meaning trimming verbose or ambiguous phrasing is a more direct lever for cutting cost/energy than simplifying the task itself.
