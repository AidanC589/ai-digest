- [**Stealing Reasoning Traces from Proprietary LLM APIs**](https://simonwillison.net/2026/Aug/11/stealing-reasoning-traces/) — Researchers found all models within a provider family shared the same encryption key for reasoning blocks; by replaying traces into weaker siblings and using prefill tricks, they extracted raw chain-of-thought in plaintext. Claude Haiku 4.5 was the easiest target. A scan of ~7,000 public traces recovered 62 API keys, 33 emails, and 33 passwords hidden inside reasoning blocks — patches are deployed but the attack surface remains worth understanding.

## Engineering & AI Workflows

- [**[AINews] How to steal a Reasoning Trace**](https://www.latent.space/p/ainews-how-to-steal-a-reasoning-trace) — The operational security implication for AI-assisted dev: if you've ever shared a Claude Code or Codex session log publicly, encrypted reasoning blobs in those traces may have been decodable and could contain secrets your model was silently reasoning about. Audit any public session exports immediately.

- [**Quoting Florian Herrengt**](https://simonwillison.net/2026/Aug/12/florian-herrengt/) — A sharp warning about *cognitive debt*: teams relying entirely on AI to write and fix code can reach a state where nobody understands the system, bugs become unfixable, and even the AI can't diagnose them because the codebase is too convoluted. The article flags this as the emerging risk for fully AI-assisted workflows — the reviewer role requires maintaining genuine system understanding, not just steering outputs.

- [**alchemy-utils 0.1a0**](https://simonwillison.net/2026/Aug/12/alchemy-utils/) — Simon Willison built and shipped a working alpha library in a single morning using Codex and GPT-5.6 Sol Ultra with TDD-first prompting: explicit instructions to use red/green pytest, commit early and often, and reference an existing similar library as a design target. The pattern (research spike → structured prompt with concrete constraints → iterative follow-up only as needed) is a replicable template for greenfield library work.

- [**Lost in Compaction: Evaluating Side-Constraint Loss under Context Compaction**](https://arxiv.org/abs/2608.11242) — Research finding directly relevant to long Claude Code sessions: current context compactors retain only **17% of session-level instructions** (e.g. "don't delete any emails until I confirm") on average, often performing worse than no compaction at all. An SC-aware extractor module achieves 90%+ retention. Until this is built into tools, repeat critical constraints after any `/compact` operation.

- [**There are no lossless transformations of natural-language text**](https://simonwillison.net/2026/Aug/11/there-are-no-lossless-transformations-of-natural-language-text/) — Every AI rewrite of your docs or specs loses information, because the model doesn't share your mental model of what you meant. The practical rule: if you can't answer "what did you mean by this line?" for every sentence in an AI-assisted document, it's not ready to ship.

## Try This

After any `/compact` in a long Claude Code session, immediately re-inject your critical session constraints as a follow-up message — something like: "Resuming after compaction. Constraints still in effect: [list them explicitly]." The COMPINT research shows compactors drop ~83% of these instructions on average, so anything you've said like "don't modify the database schema" or "always write tests before implementation" is likely gone from context. Make re-stating constraints after compaction a reflex, or add them to your `CLAUDE.md` project file so they're always reloaded.
