## Engineering & AI Workflows
- [The AI Productivity Gap](https://bjorg.bjornroche.com/management/ai-productivity-gap/) — Data-grounded analysis showing AI delivers ~15% daily time savings for senior engineers (who spend relatively little time coding) vs. ~25% for juniors; the parts AI doesn't help with — requirements analysis, system reasoning, cross-team coordination — are exactly where senior time goes, so productivity expectations need recalibrating
- [Don't be a meat proxy](https://simonwillison.net/2026/Aug/3/dont-be-a-meat-proxy/#atom-everything) — Niklas Gruhn's term for people who blindly relay AI output without reading or validating it; directly relevant to anyone reviewing AI-generated code — the review step is where you add value, not the generation step
- [Quoting David Crawshaw's prompt](https://simonwillison.net/2026/Aug/3/david-crawshaw/#atom-everything) — Concrete prompt pattern for autonomous maintenance: a nightly cron job running "fetch upstream changes to \<software\> and rebase all local changes on top of upstream; check that the software works as intended and replace the current version" — a tight, repeatable agent task worth stealing
- [Devtools must be open source (exe.dev)](https://simonwillison.net/2026/Aug/3/devtools-must-be-open-source-exedev/#atom-everything) — Simon Willison notes LLMs have made the open-source "examine and modify" promise actually practical: "tell Codex or Claude Code to checkout and build X and then come back ten minutes later" — friction for exploring unfamiliar codebases is now near zero
- [Quoting Steve Yegge](https://simonwillison.net/2026/Aug/4/steve-yegge/#atom-everything) — Steve Yegge reports Claude Opus 4.7 introduced a "just two more things" convergence failure in his coding agent framework Gas Town, where the model perpetually wanted to refine itself rather than do real work — a concrete regression to watch for if you're running long agentic loops with Opus 4.7

## Try This
Use Claude Code's new `prompt-audit` subcommand to scan your existing CLAUDE.md files, system prompts, and MCP tool descriptions for patterns optimised for older models. Run `claude prompt-audit` against your project's prompt files and review its output before your next major coding session — stale prompting patterns are a silent quality drag that's easy to miss when you're iterating fast.

## Token Saving Techniques
- [Cost-Effective Automated Judging of Natural-Language Mathematical Proofs](https://arxiv.org/abs/2608.00004) — Three cheap open-weight models (GPT-OSS 120B, DeepSeek-V4 Flash, Gemma-4 31B) match frontier judges like Claude Opus 4.7 at up to 100× lower cost; requiring unanimous agreement ("all-three-pass") maximises precision — directly applicable to any eval pipeline where you're using frontier models as judges
- [v2.1.221](https://github.com/anthropics/claude-code/releases/tag/v2.1.221) — Claude Code now reuses the cached conversation prefix across auto-mode permission decisions, reducing prompt-cache costs for parallel tool calls; the Stats panel also now shows cache read/write token breakdowns so you can actually see what you're saving
