## TL;DR
Claude Code v2.1.232 is a substantial release with subagent forking on by default, cross-session messaging, and several security fixes. As of this month, new Claude models watermark their text output at the model level — understanding how that works (and its limits) matters for AI-generated code workflows.

## General AI Developments
- [How AI text watermarking works](https://declaude.org/watermarking/) — Claude models now watermark output by subtly biasing token selection toward a secret-keyed "green" word list; the mark is invisible and survives copy-paste, but requires long text (~1,500+ words) to be statistically reliable, and short outputs remain genuinely hard to detect. Worth understanding if AI-generated code or docs will face EU AI Act compliance scrutiny after August 2026.
- [Text AI watermarks will always be trivial to remove](https://www.seangoedecke.com/text-ai-watermarks/) — A clear-eyed counterpoint: any paraphrase or light edit breaks watermarks exactly where text changes, making enforcement against bad actors essentially impossible; the real value is in bulk statistical detection of AI content at scale, not per-document proof.

## Try This
Use Claude Code's new `@SessionName` cross-session messaging to run a dedicated reviewer session in parallel with your coding session. Start a second Claude Code session named `reviewer`, then in your main coding session type `@reviewer` to send it completed diffs or function outputs for a second-pass critique — Claude will use `SendMessage` to reach it directly without confirmation prompts. This gives you a lightweight async review loop without any extra tooling, and the forked subagent inherits your prompt cache so context costs stay low.

## Token Saving Techniques
- [Claude Code v2.1.232](https://github.com/anthropics/claude-code/releases/tag/v2.1.232) — Subagent forking is now on by default, and forked subagents inherit the full prompt cache from the parent session; spawning subagents for parallelisable subtasks (tests, linting, review) now gets cache hits rather than cold-starting, which meaningfully reduces token costs in multi-agent workflows.
