## Engineering & AI Workflows
- [Humans missed 1 in 3 threats approving AI agent commands across 40k game runs](https://scalex.dev/blog/ai-agent-permissions-stats/) — Across 409k approve/deny decisions, humans averaged 66.3% threat detection. The most dangerous blind spot: `npm run <script>` commands were approved 64.7% of the time even when the underlying script contained credential-exfiltration payloads visible in the history log. The core problem is that command-level approval is structurally broken — an agent can pre-poison `package.json` or `node_modules` without triggering any approval gate at all.
- [datasette 1.0a38](https://simonwillison.net/2026/Aug/6/datasette/#atom-everything) — Security flag: a SQL injection vulnerability was patched in Datasette affecting instances that mix public and private tables in the same database. If you're using AI-generated data tooling that exposes mixed-access Datasette instances, update to 1.0a38 or 0.65.3 immediately and disable `execute-sql` on affected databases in the interim.
- [Inside vLLM: Anatomy of a High-Throughput LLM Inference System (2025)](https://www.aleksagordic.com/blog/vllm) — Deep breakdown of vLLM's engine architecture: paged attention, continuous batching, prefix caching, speculative decoding, and multi-GPU scaling. Useful mental model for anyone steering AI workflows that touch self-hosted inference — particularly the prefix caching section, which has direct cost implications.

## Try This
Given this week's data showing that `npm run` commands are approved 64.7% of the time even when payloads are visible in history: add an explicit rule to your CLAUDE.md (or equivalent agent instructions) that reads: *"Before running any `npm run <script>` command, you must output the full resolved script content from package.json and wait for explicit confirmation. Never treat a script name as inherently safe."* This forces the agent to surface the payload in its own response rather than burying it in a history log you might skim past.

## Token Saving Techniques
- [Inside vLLM: Anatomy of a High-Throughput LLM Inference System (2025)](https://www.aleksagordic.com/blog/vllm) — The vLLM breakdown covers **prefix caching** in depth: identical prompt prefixes (system prompts, few-shot examples, CLAUDE.md-style instructions) are cached and reused across requests, meaning long repeated preambles cost tokens only on the first call. If you're running batch workflows with a shared system prompt, structuring it as a stable prefix maximises cache hits and cuts inference cost significantly.
